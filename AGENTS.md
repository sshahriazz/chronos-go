## Versioning and the changelog

Full rules: docs/VERSIONING.md. What an agent must not get wrong:

- Change a customer can observe (`proto/chronos/`, `internal/modules/`,
  `internal/server/`, a service binary, a migration)? Run
  `make changelog-new KIND=… DOMAIN=… BODY="…"`. The body is the sentence a
  customer reads — not the commit subject, which here is written for engineers.
- Refactor, test, generated code, internal tool, operator plane? No entry. Put
  `Changelog: none` in the commit message instead.
- `make changelog-check` enforces both, in `make check` and in CI.
- `CHANGELOG.md` and `.changes/vX.Y.Z.md` are generated by `make release`.
  Never hand-edit them.
- Version lives in `internal/platform/buildinfo`, stamped by the Makefile. Never
  add a `var version` to a `main` package.
- The product version and the `chronos.*.v1` wire version are independent. Never
  bump one to match the other.
- Chronos is an unstable alpha: releases are tagged `vX.Y.Z-alpha.N` via
  `PRERELEASE` in the Makefile. Never empty that default as a cleanup.
