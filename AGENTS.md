## Versioning and the changelog

Full rules: docs/VERSIONING.md. What an agent must not get wrong:

- Entries are written at RELEASE time, from the diffs, by the `/release`
  procedure — never while working, and never from a commit subject.
- What a commit owes: `Changelog: none` in the message when a customer cannot
  observe it (refactor, test, generated code, internal tool, operator plane).
- `make release-input` lists every commit since the last tag and what it touched.
  `make changelog-check` validates entries, in `make check` and in CI.
- `CHANGELOG.md` and `.changes/vX.Y.Z.md` are generated by `make release`.
  Never hand-edit them.
- Version lives in `internal/platform/buildinfo`, stamped by the Makefile. Never
  add a `var version` to a `main` package.
- The product version and the `chronos.*.v1` wire version are independent. Never
  bump one to match the other.
- Chronos is an unstable alpha: releases are tagged `vX.Y.Z-alpha` via
  `PRERELEASE` in the Makefile — a channel label, not a counter. Never empty
  that default as a cleanup.

## Committing

- Commit as soon as one thing is done and green. Do not wait to be asked, and do
  not batch a session's work into one commit. Never push without being asked.
- One commit, one reason to change. Every commit builds and its tests pass.
  A dependency bump never rides along with a behaviour change.
- Conventional Commits: `type(scope): a statement about the system`. Types:
  `feat fix refactor test docs chore perf build ci`. Scope is the module.
- Body explains why, not what. Add `Changelog: none` when a customer cannot
  observe the change.
